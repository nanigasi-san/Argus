掲載文にはGarmin連携が試験機能であること、日本語の方角表示には時計の日本語設定が必要なこと、Garmin転送に対応したスマホ版ARGUS 0.9.0以降が必要なことを記載した。カバーにはリポジトリ直下の `icon.png` を使い、500×500pxへ縮小したPNGを掲載した。目・地図・ARGUSの文字を含む元の図柄を保ち、容量は111,294 bytes。初回提出時に使ったGarmin用SVGの画像は、提出後のEdit Detailsでこのカバーへ差し替え、保存後の表示も確認した。

INとOUTの画像はfr55 Simulatorでサンプル領域を表示して撮影し、実時計での通信確認を示す画像としては扱っていない。

## 提出ファイルと検証

PR#109のコミット `e32366b460ae750c981b4a4c6c279852ea577f04` を基準にした。開発用manifestのバージョンは0.6.0のまま保ち、提出用manifestだけを0.1.0、製品ID `fr55` のみにして書き出した。監視と削除ACKの実装は開発版0.6.0と同じで、バージョン番号だけで停止機能の互換性を判定しない。

| 項目 | 結果 |
| --- | --- |
| ファイル | `build/garmin-store/ARGUS-0.1.0-fr55.iq` |
| 容量 | 45,407 bytes |
| SHA256 | `1089EFD4E6EB9A6494D98D187D85BEFEE2834CD6BC2D890A1DA53E525CD38041` |
| 書き出し | `monkeyc -e -r -y <既存の署名鍵> -l 0` で成功 |
| ローカル署名検証 | SDKの `VerifyingUtils.verifyIqFile()` がtrue。パッケージの公開鍵と既存署名鍵の公開鍵も一致 |
| ストアの読み取り | AppID、0.1.0、Data Field、ForeAthlete 55 / Forerunner 55を認識 |
| 提出の受理 | アプリ詳細ページへ移動し、`App pending` と `0.1.0 (Internal: 1)` を表示 |

提出元と同じコミットの[Garmin Tests CI](https://github.com/nanigasi-san/Argus/actions/runs/37123436635)は、26件を含む全Monkey Cテストで成功している。提出ファイルは既存の開発者署名鍵でローカル生成したもので、CIの一時署名鍵で作ったファイルは使用していない。秘密鍵とビルド生成物はGitへ含めていない。

初回のファイル検証画面は緑の `Status: Verified` と `Signature check failed.` を同時に表示した。提出ファイル自体の署名検証は成功し、[Garmin側の不具合報告CIQQA-4716](https://forums.garmin.com/developer/connect-iq/i/bug-reports/first-app-upload-status-verified-but-signature-check-failed-sdk-9-2-0)にも同じ初回登録・SDK 9.2.0の症状が記録されている。最終Submit後は正常に受理され、審査待ちになった。提出後のEdit Detailsでは `Signature: Verified` と表示されている。

## スマホ版と公開ポリシー

提出時点のiOS・Androidの公開版0.8.2にはGarmin転送機能がない。Garmin転送は0.9.0で追加しており、スマホ版の公開前は一般ユーザーが連携できない。ユーザーが公開順を確認し、Garmin版を先に審査へ送ることを指定した。

argus-lpの別セッションで公開プライバシーポリシーを日英で更新し、[コミットd4ce6b0](https://github.com/nanigasi-san/argus-lp/commit/d4ce6b0b2a976a75e570d796f5bd642ca2638b0f)をmainへpushした。公開URLでも、Garminへの範囲転送・保存、転送後12時間のRun開始期限、Run終了時の削除、一時停止時の保持、手動停止の削除ACKを確認した。開始期限だけでは自動削除されない点も記載している。
